### 2.4 Two environmental fixes, neither a code defect

The merged suite came up **56 failed, 14 errors**. Both causes were local environment, not code:

1. **`duckdb` was not installed.** It is declared in `backend/pyproject.toml`, just absent from the
   local venv. `pip install --dry-run duckdb` first (the practice from the 11 Aug log): clean, no
   dependency churn, installs `duckdb 1.5.5` alone.
2. **The local Postgres `datasets` table predated the version-lineage columns.**
   `Base.metadata.create_all` creates missing *tables*; it does not `ALTER` existing ones, so
   `root_id` did not exist and every dataset write failed. The table holds **real local data** (125
   datasets, 261 users, 241 runs), so it was **migrated, not dropped**: the five new columns added
   with `ADD COLUMN IF NOT EXISTS`, all 125 existing rows backfilled to `root_id = id, version = 1`
   (they are all original uploads), then `NOT NULL`, the two self-referential FKs, and the indexes.

> **Carry this forward:** there is no migration tool in this project. Any teammate pulling this
> merge onto an existing database hits the same wall. Either run the same `ALTER`s or drop the
> `datasets` table and let `create_all` rebuild it — the SQL is in the merge commit message.

## 3. What was built

*Phase 2 item 2.4, written test-first: 40 tests in `tests/agents/test_chart_builders.py` and 27 in
`tests/backend/test_export_charts.py`, all failing before any implementation existed.*

### 3.1 The four approximated types now have real builders

Previously `visualization_agent.py` routed these to stand-ins, so **the chart the planner asked for
and the chart the reader saw were different charts**:

| Directive | Was served by | Now |
|---|---|---|
| `grouped_bar` | plain category-frequency bar | categorical feature **cross-tabulated by target class** |
| `box_by_class` | boxplot that ignored the class | **one box per class**, five-number summary each |
| `pairplot` | a single cluster scatter | **every pairwise panel** over the top numeric columns |
| `highlighted_scatter` | an unmarked scatter | scatter with **IQR-outlier rows flagged** |

Each returns `None` when the data cannot support it and the router falls back to the old stand-in, so
the real chart is the default whenever drawable and **a directive never yields an empty slot**
(`test_conditioned_run_never_returns_an_empty_slot` asserts this across all five task types).

Two choices worth defending:
- **`box_by_class` picks its column by class separation**, scaled by the column's own spread. The old
  fallback could not show separation even where it existed, because it never split by class.
- **`highlighted_scatter` flags on the same IQR bounds `MiningAgent` reports**, so the chart and the
  findings agree. Sampling keeps *every* flagged row — dropping anomalies from an anomaly chart would
  defeat it.

### 3.2 Two absent types added

`violin` (binned density profile + five-number overlay) and `line` (a numeric column's trend over the
time axis). Both emit **bands/points computed from the data**, not kernel estimates — the counts are
exactly the frame, so a reader can check them and there is no bandwidth parameter to justify.

### 3.3 The renderers

All six wired through the spec builder, the React renderer, and the ReportLab exporter, keeping the
**one source of truth, two renderers** rule (the agent emits plain dicts; it never draws).

Two honest concessions in the PDF, noted in code comments: `box_by_class` renders as a per-class
summary table, and `pairplot` panels are min-max scaled and overlaid rather than drawn as a true
grid. The on-screen versions are the real charts.

## 4. Bugs found and fixed

1. **`scatter` and `missingness_matrix` rendered as blank cards in the UI.** Both are emitted by the
   agent — `scatter` on every regression and anomaly goal, `missingness_matrix` on every reporting
   goal — but neither had a branch in the report view's dispatch. The card drew its title and then
   nothing. *Found independently by a teammate on the integration branch too; theirs is the version
   that survived the merge.*

2. **Chart captions were never XML-escaped.** The 12 Aug fix routed the *agent trail* through
   `_esc()` but missed `_chart_flowables`. Chart titles quote column names back — "Distribution of
   `'<revenue>'`" — so a column named `<revenue>` was silently swallowed and one containing `&`
   would crash the whole export with a 500. Same bug class, same reachability, different function.

3. **The line chart could never have fired on real data.** It required `datetime64`, but CSV
   ingestion does not infer date types — an uploaded file arrives with the date column as text. The
   chart would only ever have appeared in tests that build the frame by hand, which is the worst
   kind of passing feature. Text columns are now parsed as a time axis when ≥90% of values parse and
   their median length is ≥6 characters; the length guard is what stops category codes like `"3"`
   becoming a time axis.

4. **`grouped_bar` chose the timestamp column.** Same root cause: text dates are typed *categorical*
   by the profiler, so the date column was picked as the feature to group by. A grouped bar over 400
   distinct timestamps, truncated to its 8 busiest, is noise. Selection now excludes the detected
   time axis, caps distinct values at 25, and prefers the **lowest-cardinality** candidate.

> Bugs #3 and #4 were invisible to a green unit suite and only appeared when the pipeline was run on
> an actual CSV. For this agent, hand-built fixtures and ingested data differ in **dtype**, and dtype
> is what chart selection keys on. Run the pipeline, not just the tests.

## 6. Gemini — configuring the LLM

The merge brings the project's **first real LLM call**. It is used in three places, all opt-in:
follow-up chat "LLM mode", "Explain further" on a finding, and ask-in-English → SQL in the workbench.

- Set `GEMINI_API_KEY` in `.env` (the key is now listed there, empty, with a comment).
- **Leave it empty and nothing breaks.** Every call site guards on `client.is_configured` and falls
  back to the deterministic RAG path. That is what keeps the suite green with no key present, and it
  is worth stating in the report — the LLM is an *enhancement layer*, not a dependency.
- Model is pinned to `gemini-2.5-flash`. `gemini-2.0-flash` was retired mid-project and the `-latest`
  alias was observed returning 503s. If it starts 404ing, list what is live on the key:
  `GET https://generativelanguage.googleapis.com/v1beta/models?key=…`
- **Citation integrity is preserved.** `explain_agent` retrieves from the knowledge base *first* and
  only lets the model synthesise on top, so output always carries a citation or an honest
  "nothing found" — never free-floating model text. The UI badges which path produced the answer.
- **NFR-03 is still open.** `llm_client.py` raises `LLMError` on failure; there is no retry with
  exponential backoff. The LLM existing does not close that requirement.

## 7. ⚠️ The merge moved the headline metric — decision recorded

**This is the most important thing in this log.** Read it before quoting any evaluation figure.

A teammate broadened the `reporting` task type's computations to include `correlation`,
`feature_importance` and `iqr_outliers` (commit `5e598f0`). The motivation is sound and documented in
their code comment: reporting is the fallback for broad, unfocused goals, and it was previously
computing so little that the visualization step had nothing to build from — *the most common goal
type produced the sparsest results*.

But reporting now overlaps the other four task types substantially, and two of the added
computations sit outside reporting's hand-labelled relevance set. The harness therefore moves down:

| Metric | Before merge | After merge |
|---|---|---|
| Computation divergence | 0.940 | **0.836** |
| Chart divergence | 0.979 | **0.920** |
| Task-relevant precision | 1.000 | **0.883** |
| Recall / F1 | 0.601 / 0.749 | unchanged in direction, see `results.md` |
| Citation coverage | 1.000 | **1.000** |
| Baseline divergence | 0.000 | **0.000** |

The alternatives were measured before deciding, not guessed:

| Option | Comp. divergence | Precision | Cost |
|---|---|---|---|
| **A — keep as merged** ✅ **chosen** | 0.836 | 0.883 | none to the code |
| B — narrow reporting again | 0.869 | 0.950 | reverts a teammate's fix; reporting loses its feature-importance chart |
| C — widen the relevance set | 0.836 | ~1.000 | post-hoc ground-truth editing in MAGE's favour |

**Decision: option A. Nothing was edited in response to the score.** Rationale:

- 0.836 against a baseline of 0.000 still carries the claim decisively. The thesis is not at risk.
- Option C is precisely the move the 11 Aug log flags as suspect, and an examiner is entitled to
  object to it. Having already made one such edit (`shap_attribution`), a second would be a pattern.
- Option B trades a real, user-facing improvement for ~0.03 of a metric.
- **There is a genuinely good framing here, not a excuse:** `reporting` is the *no-specific-goal*
  fallback. It is the one task type where conditioning arguably *should* be weakest, because there
  is no goal to condition on. Broadening it traded measured divergence for output richness on
  unfocused goals, and saying so demonstrates the trade-off was understood rather than hidden.
