## 4. What was built

*Phase 2 item 2.4, written test-first: 40 tests in `tests/agents/test_chart_builders.py` and 27 in
`tests/backend/test_export_charts.py`, all failing before any implementation existed.*

### 4.1 The four approximated types now have real builders

Previously `visualization_agent.py` routed these to stand-ins, so **the chart the planner asked for
and the chart the reader saw were different charts**:

| Directive | Was served by | Now |
|---|---|---|
| `grouped_bar` | plain category-frequency bar | categorical feature **cross-tabulated by target class** |
| `box_by_class` | boxplot that ignored the class | **one box per class**, five-number summary each |
| `pairplot` | a single cluster scatter | **every pairwise panel** over the top numeric columns |
| `highlighted_scatter` | an unmarked scatter | scatter with **IQR-outlier rows flagged** |

Each dedicated builder returns `None` when the data cannot support it — no target column, fewer than
two numeric columns, no outliers — and the router then falls back to the old stand-in. So the real
chart is the default whenever it is drawable, and **a directive still never yields an empty slot**.
`test_conditioned_run_never_returns_an_empty_slot` asserts that across all five task types.

Two design choices worth defending:

- **`box_by_class` picks its column by class separation**, scaled by the column's own spread — the
  column that best distinguishes the classes is the one worth the slot. The old fallback could not
  show separation even where it existed, because it never split by class.
- **`highlighted_scatter` flags on the same IQR bounds `MiningAgent` reports**, so the chart and the
  numbers in the findings agree. Sampling keeps *every* flagged row; dropping anomalies from an
  anomaly chart would defeat it.

### 4.2 Two absent types added

`violin` (binned density profile + five-number overlay) and `line` (a numeric column's trend over
the dataset's time axis). Both are emitted as **bands/points computed from the data**, not kernel
estimates — the counts are exactly the frame, so a reader can check them, and there is no bandwidth
parameter to justify in a viva.

### 4.3 Planner wiring — and why this was decided *before* re-running the harness

`violin` and `line` were added to the **reporting** task type only. Recorded here in the order it
happened, because the alternative reads badly: they are distribution/trend *profiling* charts, and
reporting is their home. They are deliberately **not** added to the supervised task types, where
`box_by_class` already answers the distribution question against the target and a time axis is
incidental. Both degrade to nothing when the data cannot support them, so reporting never loses a
chart by having asked.

⚠️ **This moves chart divergence, and the direction favours MAGE — so read it with that in mind.**
Chart divergence went **0.942 → 0.979** because reporting's chart set is now more distinct from the
other four. Two mitigating facts, both checkable:

1. **Computation divergence — the headline number — did not move.** It is still **0.940**, because
   nothing in `_MINING_DIRECTIVES` was touched. The claim the project is actually evaluated on is
   unaffected by this session.
2. **Chart divergence has no hand-labelled ground truth** (only `TASK_RELEVANT_COMPUTATIONS` does),
   so unlike the 11 Aug `shap_attribution` edit, nothing here required editing a relevance set.
   Precision stays 1.000 and recall 0.601 for exactly that reason.

### 4.4 The renderers

A chart type has to exist in three places — the spec builder, the React renderer, and the ReportLab
exporter. All six were wired to all three, keeping the project's **one source of truth, two
renderers** rule (the agent emits plain dicts; it never draws).

Two honest concessions in the PDF, both noted in code comments:
- `box_by_class` renders as a per-class summary table. A grouped box plot is not worth hand-drawing
  in ReportLab, and the table carries the same comparison legibly at report width.
- `pairplot` panels are min-max scaled into a shared unit square and overlaid as colour series, since
  a true panel grid is not available at that width. The JSON export keeps the unscaled points.

## 5. Bugs found and fixed

1. **`scatter` and `missingness_matrix` rendered as blank cards in the UI.** Both are emitted by the
   agent — `scatter` on every regression and anomaly goal, `missingness_matrix` on every reporting
   goal — but neither had a branch in the report view's dispatch. The card drew its title and then
   nothing. Present since those types were added; found while mapping the render contract, not by a
   test. Both now dispatch (`ScatterPlot`, and `BarChart` for missingness).

2. **Chart captions were never XML-escaped.** The 12 Aug fix routed the *agent trail* through
   `_esc()` but missed `_chart_flowables`. Chart titles quote column names back — "Distribution of
   `'<revenue>'`" — so a column named `<revenue>` was silently swallowed and one containing `&`
   would crash the whole export with a 500. Same bug class, same reachability (any column name),
   different function. Now escaped, with a regression test.

3. **The line chart could never have fired on real data.** It required `datetime64` dtype, but CSV
   ingestion does not infer date types — an uploaded file arrives with the date column as text. The
   chart would only ever have appeared in tests that build the frame by hand, which is the worst
   kind of passing feature. Found by running the pipeline end-to-end rather than by the unit tests,
   which used a hand-built frame and passed happily. Text columns are now parsed as a time axis when
   ≥90% of values parse and their median length is ≥6 characters — the length guard is what stops
   category codes like `"3"` becoming a time axis. Both cases are now pinned by tests.

4. **`grouped_bar` chose the timestamp column.** Also found end-to-end: because an uploaded CSV
   leaves dates as text, the profiler types them *categorical*, and the date column was being picked
   as the feature to group by. A grouped bar over 400 distinct timestamps, truncated to its 8
   busiest, is noise. Feature selection now excludes the detected time axis, caps distinct values at
   25, and prefers the **lowest-cardinality** candidate. On the E2E frame it correctly picks
   `region` over `order_date`.

> Both #3 and #4 were invisible to a green unit-test suite and only appeared when the pipeline was
> run on a CSV. Worth remembering: for this agent, hand-built fixtures and ingested data differ in
> dtype, and dtype is what the chart selection keys on.
