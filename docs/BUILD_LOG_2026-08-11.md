## 2. First finding: the test suite was not green

The continuation plan claimed 177 passing tests. Reality on checkout: **210 collected, 25 failing.**

All 25 failures were environmental, not code defects — every one was in `tests/backend/` and every
one was the same root cause: **Postgres was not running** on `:5432`, so `asyncpg` could not
connect. Starting the `postgres` service via `docker compose up -d postgres` fixed all 25 at once.

**Takeaway for the report and for anyone running this:** `tests/backend/` requires Postgres.
`PYTHONPATH=. pytest tests/` on a machine without it will show 25 failures that mean nothing about
the code.

## 3. What was built

### 3.1 Empirical evaluation harness — Objective 7 (`evaluation/`)

The project's entire validation claim, which had no code at all.

```bash
PYTHONPATH=. python -m evaluation.harness     # → evaluation/results.json + results.md
```

Six modules: `datasets.py` (5 pinned datasets — 4 scikit-learn built-ins plus one seeded synthetic
set with planted clusters, outliers, imbalance and missingness), `baseline.py`, `harness.py`,
`metrics.py`, `report.py`, plus `BASELINE_VALIDATION.md`. 91 tests in `tests/evaluation/`.

**The experiment:** hold the dataset constant, vary only the natural-language goal — 5 datasets ×
5 goals = 25 runs. Any difference between runs is attributable to goal-conditioning and nothing
else.

**Results (25 runs):**

| Metric | MAGE | AutoEDA baseline |
|---|---|---|
| **Cross-goal computation divergence** | **0.940** | **0.000** |
| Cross-goal chart divergence | 0.942 | 0.000 |
| Task-relevant precision | 1.000 | 0.400 |
| Task-relevant recall | 0.601 | 0.539 |
| Task-relevant F1 | 0.749 | 0.458 |
| Citation coverage (FR-03) | 1.000 | — |
| Goal classification accuracy | 1.000 | — |
| Max runtime (FR-05) | **2.09s** | — |

**The baseline is validated, not asserted.** It is a pinned declarative spec of what
ydata-profiling computes, and it was checked against a live ydata-profiling 4.18.4 run on all five
datasets: **exact match, zero discrepancies**, and identical across every dataset. Recorded in
`evaluation/BASELINE_VALIDATION.md`. ydata-profiling is deliberately **not** a project dependency
because installing it forces `pandas<3` — see §5.

**Caveats to carry into the report, not to hide:**
- MAGE's precision of 1.000 is **ceilinged**. It shows the planner emits nothing outside the
  relevant set; it cannot distinguish a good conditional pipeline from an excellent one. Recall is
  the more informative number for MAGE.
- The baseline reaches comparable recall **by brute force** — it runs everything, every time. Its
  low precision is what that costs. F1 is the fair single comparison.
- Relevance sets are hand-labelled in `evaluation/metrics.py`, deliberately **not** derived from
  `planner.py`; deriving them from the system under test would make precision circular.

### 3.2 WebSocket step streaming — M7 + M8

`WS /analysis/stream`, plus a live agent trail in the UI. 24 tests in `tests/backend/test_stream.py`.

- `OrchestratorAgent.run()` gained `on_step=None`. Default path is byte-identical, so no existing
  test changed. Callback exceptions are logged and swallowed — a dead client cannot abort a run.
- `OrchestratorService.run()` now calls the agent via `asyncio.to_thread`. **This was required, not
  cosmetic:** on the event loop the callback fires but nothing can be *sent* until the run ends, so
  it would have batched while looking like streaming. It also stops one analysis blocking every
  other request.
- Auth from a `?token=` query param (browsers cannot set headers on a WebSocket), applying exactly
  the checks `get_current_user` does. Tests cover garbage tokens, refresh-tokens-used-as-access,
  and valid-signature-but-unknown-user.
- Step frames omit the heavy `output` payload; the full result rides on the terminal `complete`
  frame and is what gets persisted.
- Frontend: `lib/use-analysis-stream.ts` hook + `components/agent-stream.tsx`, wired into the new
  analysis page. All four agents render greyed up front, then fill in live.

**Verified genuinely incremental** (live uvicorn, real websocket client, 4,000 rows):
`Ingestion t+13.7ms · Mining t+2.0s · Visualization t+2.0s · Recommendation t+3.7s · complete
t+3.8s`. First frame at 13.7 ms of a 3.8 s run.

### 3.3 SHAP feature attribution — Objective 5 / M6

`shap.TreeExplainer` over a small `GradientBoosting` model fitted to the detected target. **Real
SHAP, not the permutation fallback.** 34 tests in `tests/agents/test_feature_attribution.py`.

- Strictly opt-in on a new `shap_attribution` token added to the classification and regression
  entries in `planner.py`. It does **not** run for clustering / anomaly / reporting goals, and the
  unconditioned default profile is untouched. Tests assert presence *and* absence.
- New `feature_attribution` key on the mining result; reuses the `feature_importance` render type
  so frontend and ReportLab both draw it unchanged, but with a distinct title naming target and
  method so it is never confused with the unsupervised PCA ranking.

**Two honesty features built into the output — keep them:**
- `method` names what actually ran. On SHAP failure it falls back to
  `sklearn.inspection.permutation_importance` and **says so**. *Quote this field in the report;
  don't assume SHAP.*
- `model_score` is the fitted model's train score. Attributions from a model that cannot predict
  the target are not meaningful, and this is what lets a reader judge that.

**Checked against known ground truth**, not just for well-formedness: SHAP ranks `customer_age`
top for churn (the generator ties churn to the age-defined segment) and `s5`/`bmi` top on sklearn's
diabetes (the known dominant features). Tests plant a driver against a pure-noise feature and
require the driver to win by >3×.

### 3.4 Third expertise register — FR-04 / M6

| Value | Spec audience | Field | Content |
|---|---|---|---|
| `beginner` | Beginner | `text_plain` | Plain language, 2 sentences |
| `intermediate` | **Analyst** *(new)* | `text_analyst` | Finding + 4 sentences, attributed inline |
| `expert` | Data Scientist | `text_technical` | Full excerpt, markdown intact |

Verified over HTTP — same dataset, same goal, three levels: **371 / 1062 / 1101 chars**, all three
renderings distinct. Frontend labels updated to Beginner / Analyst / Data Scientist; stored enum
values unchanged (they are the API contract and persist on the user record). Registers fall back
down the chain (`analyst → technical → insight`) so runs persisted before `text_analyst` existed
still render prose.

**The first implementation was wrong and the tests caught it.** Separating registers by truncation
length alone collapses on single-sentence KB chunks — plain and analyst came out byte-identical, so
FR-04 would have silently failed for exactly the recommendations whose source is shortest. The
analyst register now differs **structurally**: it names the methodology inline ("Per Clustering
Method Selection: …"), which holds at every chunk length.

### 3.5 Embedding model warm-up (side fix, real impact)

Streaming made a latent problem visible: the sentence-transformer model loads lazily on first use,
so the first analysis after any restart stalled ~13s on `RecommendationAgent`. Added
`rag.embeddings.warm_up()`, kicked off in the background from the FastAPI lifespan.

**Measured on a real server: total run 16.4s → 3.8s.** The API still starts serving immediately.

## 4. Bugs found and fixed

1. **WebSocket DB connection leak.** `Depends(get_db)` teardown does not run reliably for WebSocket
   routes — every connection that touched the database orphaned its connection until SQLAlchemy's
   garbage collector reclaimed it (11 `SAWarning`s per test run; zero in the REST tests). Fixed by
   opening the session explicitly with `async with async_session()`.
   ⚠️ **If you add another WebSocket route, do the same — do not use `Depends(get_db)` there.**
   *(My first fix attempt was wrong: I blamed the background task. Isolating leaks per test class
   showed the validation tests — which never run an analysis — leaked most, which pointed at the
   dependency.)*
2. **FR-05 was being measured wrong by ~50×.** The first harness run reported 16.02s max; that was
   the embedding model loading, landing entirely on whichever run went first. A discarded warm-up
   run dropped it to 1.8s. Without that, a startup cost would have been reported as an analysis cost.
3. **Register collapse on short chunks** — see §3.4.

## 5. Dependency decisions (both cost something — know why)

**ydata-profiling: installed, used once, then removed.** It downgraded `pandas 3.0.3 → 2.3.3`,
`numpy 2.5.0 → 2.3.5`, `scipy 1.18.0 → 1.16.3`, and broke `tests/agents/test_ingestion_agent.py`
(pandas 3 reports `str` dtype where pandas 2 reports `object`). It also needs `setuptools<81` for
`pkg_resources`. Since the pinned baseline spec was proven exact against it, the validation was
captured and the stack restored. `--live-baseline` remains available and degrades gracefully.

**shap: installed and kept.** It pulls `numba`, which pins `numpy<2.5`, so the stack now sits at
**numpy 2.4.6**. pandas 3.0.3 and scipy 1.18.0 are untouched and all 385 tests pass.

> **Practice worth keeping:** run `pip install --dry-run <pkg>` *before* installing anything here.
> That is how the numpy downgrade was caught in advance, after ydata-profiling had already
> silently downgraded pandas earlier in the day.

## 7. Honesty guide — additions from today

The existing list in `CONTINUATION_PLAN.md` §8 still stands. Today adds:

**Claim confidently**
- Goal-conditioning is **measured, not asserted**: 0.940 cross-goal divergence against a baseline's
  0.000, on a baseline verified exact against the real ydata-profiling.
- FR-05 is benchmarked: max 2.09s across 25 runs, well inside the 60s budget.
- SHAP attribution recovers known ground truth on two independent datasets.
- 385 tests, including cross-user isolation on every export path and auth parity on the WebSocket.

**Concede plainly**
- Precision of 1.000 is ceilinged and should not be presented as a quality score.
- The evaluation's relevance sets are **hand-labelled**, and one was edited today (adding
  `shap_attribution`) in a direction that *raises* MAGE's score. The justification is
  methodological and there is a dated CHANGE LOG comment above the constant; a reader is entitled
  to disagree and re-run with the original sets.
- Recommendation text is deterministic template paraphrase, not LLM synthesis. The three registers
  differ by how much methodology they keep and whether they attribute it — not by genuine rewriting.
- Markdown tables are dropped from all recommendation text (§6.1).
- Analysis is synchronous per request; there is no job queue. The WebSocket streams a synchronous
  run from a worker thread.
